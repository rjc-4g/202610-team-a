# 日程調整アプリ 要件定義書

- ステータス: 要件・技術スタック確定(10 時間版)
- 作成日: 2026-10-21

## 1. 目的・前提

- 社内の限られたメンバー(最大 10〜15 人)で、会議などの日程を調整するための Web アプリ。
- **開発期間は 10 時間(1 人で実装、AI 支援あり)**。この範囲に収まる機能に絞る。ハーネス構築(2 章)はこの 10 時間とは別枠とする。
- **最優先事項は「未回答者の把握」**。管理者が管理画面で未回答者を確認し、催促できることを重視する。
- **本アプリは学習目的**。成果物の完成度に加え、2 章に挙げるスキルの習得を目的に含める。
- **ゴールは開発環境で動作すること**。本番環境の構築・運用(本番サーバ、本番用の接続設定など)は対象外とする。
- 当面は単発イベントのみを対象とする。繰り返し・複数回への拡張は将来検討。

## 2. 学習目標(習得したいスキル)

学習目標を満たすことも要件とする。

| スキル | 要件 |
|---|---|
| Git / GitHub | GitHub リポジトリで管理する。`main` は直接コミットせず、機能ごとにブランチを切り Pull Request でマージする。タスクは Issue で管理する。 |
| Docker | アプリ本体と DB(**PostgreSQL**)をコンテナ化し、`docker compose up` で開発環境全体が起動する。 |
| AI(AI 支援開発) | Claude Code を用いて実装する。**設計の前に、AI エージェントのハーネス(Skills、hooks、`CLAUDE.md` など)を構築**し、開発に使う。 |

- アプリ自体への AI 機能の組み込み(Claude API の利用)は対象外とする。

## 3. 利用者と権限

| 区分 | 人数 | できること |
|---|---|---|
| 管理者 | 基本 1 人 | イベントの作成、日程の確定 |
| 一般ユーザ | 事前登録された社内メンバー | 自分の回答の登録・修正、回答状況の閲覧 |

- 利用者は事前登録制。ユーザの追加・削除は発生しうる。
- ログイン必須(**ID・パスワードの簡易認証**)。一般ユーザは他人の回答を編集できない。
- ロールはユーザ情報の項目として持ち、将来の管理者複数化・権限分割に備える。

## 4. 機能要件(10h スコープ)

### 4.1 イベント作成(管理者)

- タイトル、回答期限、候補日時(開始日時+所要時間)を登録する。
- 参加者を指定し、**必須 / 任意**に区分する。

### 4.2 回答(ユーザ)

- 候補日ごとに ○ / △ / × を選択する。
- 備考欄(コメント)を入力できる。
- 回答期限内であれば修正できる。**期限後の回答・修正はできない**(今回はスコープ外)。

### 4.3 回答状況の一覧

- 全員の回答を一覧表示する。回答内容は全員に公開する。
- **管理画面で、イベントごとに未回答者(全候補日に未入力のユーザ)を明示的に表示する**。
  - 未回答者の氏名を一覧表示し、回答済み人数 / 参加者数も表示する。
  - 必須参加者の未回答は、任意参加者と区別して目立たせる。

### 4.4 最適日の提案と確定

全員の回答が出そろった時点で、以下の順で候補を提示する。

1. 必須参加者全員が参加可能な日を優先する。
2. 該当する日がなければ、参加可能人数が最大の日を優先する。

- **人数の数え方**: ○ = 1 人、△ = 0.5 人、× = 0 人として合計する。
- **同点の場合**: 同点の候補をすべて提示し、管理者が選んで確定する。
- 提案は参考情報で、**確定は管理者が行う**(確定した候補を保存し、イベントを「確定」状態にする)。
- **「参加可能」の判定**: 必須参加者の判定では、○ と △ を「参加可能」とし、× のみ不可とする。

### 4.5 ユーザ登録

- ユーザ情報(氏名、ログイン ID、初期パスワード、ロール)は DB に保存する。
- 初期登録は CSV / JSON から取り込むスクリプトで行う。
- ユーザの削除は物理削除ではなく無効化とし、過去の回答を残す。
- ユーザ管理画面(一覧・追加・無効化)は、**余った時間で追加する「できれば」枠**とする。

## 5. 画面一覧(想定)

| 画面 | 対象 |
|---|---|
| ログイン | 全員 |
| イベント一覧 | 全員 |
| イベント詳細 / 回答入力 / 回答状況一覧 | 全員 |
| イベント詳細内の未回答者表示 | 管理者 |
| イベント作成 / 日程確定 | 管理者 |
| ユーザ管理 | 管理者(「できれば」枠) |

## 6. データ(概略)

- ユーザ: ID、氏名、ログイン ID、パスワード(ハッシュ)、ロール、有効 / 無効
- イベント: タイトル、回答期限、状態(回答受付中 / 確定)、確定した候補
- 候補日: イベント、開始日時、所要時間
- 参加者: イベント、ユーザ、区分(必須 / 任意)
- 回答: 候補日、ユーザ、○△×、備考、更新日時

## 9. 将来検討: 回答リマインド通知(メール)

今回は実装しないが、追加する場合の方針を残す。

- **内容**: 回答期限の 1 日前に 1 回、未回答者のみに個別のメールを送る。リマインド頻度のイベント別変更は行わない。
- **実現方式**: アプリ内のスケジューラが 1 時間ごとに「期限まで 24 時間以内かつ未送信」のイベントを探し、未回答者へ送信する。送信後にイベントへ送信日時を記録して重複送信を防ぐ。
- **開発環境**: Docker で開発用メール受信サーバ(Mailpit を想定)を起動し、アプリは SMTP(ポート 1025)へ送信、Web 画面(ポート 8025)で内容を確認する。
- **追加で必要になるもの**: ユーザのメールアドレス項目、イベントの送信日時項目、定期実行の仕組み。
- **本番化する場合**: 本番用の SMTP、送信元アドレス、迷惑メール判定対策、常時稼働するサーバ。
