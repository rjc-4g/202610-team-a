# Issue からブランチを切って作業を始める

引数: Issue 番号(省略時は、依存が解消済みで未完了の Issue を `gh issue list` から選んで提案し、ユーザに確認する)。

## 手順

1. **Issue 確認**: `gh issue view <番号>` で概要・受け入れ条件・依存・参照を読む。
   - 依存先の Issue が未完了なら、着手せずユーザに伝える。
   - 参照先の `docs/requirements.md` の該当章を読む。要件と Issue が食い違うときは実装せずユーザに確認する。
2. **ブランチ作成**: 作業ツリーがクリーンか `git status` で確認し、`develop` から切る。
   - `git switch develop` のあと `git switch -c <種別>/<内容>`。
   - 名前は `feature/<内容>` / `fix/<内容>` / `docs/<内容>`(CLAUDE.md の命名)。内容は英小文字とハイフン。
   - `main` / `develop` へは直接コミットしない。
3. **計画の提示**: 次を短くまとめてユーザに見せる。着手の承認は求めなくてよいが、スコープ外の変更が必要なら先に確認する。
   - 受け入れ条件ごとの作業内容
   - 触るファイル
   - 動作確認の方法(自動テスト / 手動確認)
   - 要件書のスコープ外・「できれば」枠に当たる項目がないか

## 注意

- コミット・push・PR など外部に影響する操作はここでは行わない(承認が必要)。
- 1 Issue = 1 機能。依頼範囲を超えて機能や抽象化を足さない。
