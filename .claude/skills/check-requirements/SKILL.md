# 要件書との差分を確認する

引数: 対象(省略時は `develop` との差分)。例: Issue 番号、章番号、ファイル。

## 手順

1. `docs/requirements.md` を全文読む。対象が Issue なら `gh issue view` の受け入れ条件も読む。
2. 対象の変更を把握する(`git diff develop...HEAD`、関連ファイルの Read)。
3. 次の観点で突き合わせる。
   - **充足**: 要件・受け入れ条件を満たしているか(章番号を添えて列挙)
   - **不足**: 満たしていない、確認できていない項目
   - **食い違い**: 要件書と実装・Issue の記述が合わない箇所
   - **スコープ外**: 8 章(スコープ外)や「できれば」枠の機能が混ざっていないか
   - **権限**: 管理者専用処理・他人の回答編集がサーバ側で検査されているか(画面の非表示だけに頼っていないか)
   - **秘密情報**: パスワードのハッシュ化、秘密情報がコード・Git に入っていないか
4. 結果を表で報告する(項目 / 要件の章 / 判定 ○△× / 根拠のファイルと行)。

## 注意

- 読み取り専用。コードも要件書も勝手に直さない。
- 食い違いがあるときは、どちらを正とするかユーザに確認する。要件を変えるときは、コードより先に `docs/requirements.md` を更新する。
- 確認できなかった項目は「未確認」と書く。推測で○にしない。
