# コミット・PR を準備する

**このスキルは案を提示するところまで。** `git commit` / `git push` / `gh pr create` は、案を見せて操作ごとに明示的な承認を得てから実行する。包括的な指示(「進めて」等)は承認とみなさない。

## 手順

1. **状況確認**: `git branch --show-current`、`git status`、`git diff`(必要なら `--staged`)、`git log develop..HEAD --oneline`。
   - 現在のブランチが `main` / `develop` なら止めてユーザに伝える。
   - 秘密情報(環境変数ファイル、認証情報)が含まれていないか確認する。
2. **コミット案**(`.gitmessage` の形式): 1 コミット 1 目的。複数目的なら分割案を出す。
   - `<種別>: <日本語で簡潔に>`(種別: feat / fix / docs / chore / infra / refactor / test)
   - 本文に何を・なぜ。関連 Issue は `Refs #番号`
   - 末尾に Co-Authored-By 行(システムの指示に従う)
   - 対象ファイルを明示する
3. **PR 案**(`.github/pull_request_template.md` の見出しをそのまま使う): 概要 / 変更内容 / 関連 Issue(完了なら `Closes #`、途中なら `Refs #`)/ 動作確認 / レビューしてほしい点 / チェックリスト。
   - 動作確認は、実際にやったことと結果だけを書く。できなかったものは未確認と明記する。
   - マージ先は `develop`。末尾に PR 用の生成表記(システムの指示に従う)。
4. **承認を得て実行**: コミット → push → PR 作成を、それぞれ別の操作として確認する。
   - 宛先(ブランチ、リモート)と内容を示す。承認は 1 操作 1 回限り。
   - 本文に環境変数ファイル名を書くと hook に誤検知されることがある。その場合は表現を言い換える。
